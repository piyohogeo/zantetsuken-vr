# 切れない車の片の調査(2026-11-14、調査完了)

通常プレイ(Link、PC Development Player、D3D12)で「斬っても切れない」と見えた片を 5 件選んで保存し、原因を調べた記録。結論は、**車の Convex 集合が車体 Mesh の内部を覆いきっていないために、見える面と斬撃の命中対象が離れていた**こと。切断処理の不具合ではない。利用者が仕様どおりの挙動として受け入れ、本件は原因判明・調査完了で閉じた。

## 調査対象

- 同じ車 `car_030` に由来する、NPC ではない 5 片(選択番号 #1〜#5)。5 件とも同じ根の fragment から、通常切断を 16〜26 回経て生まれている。
- 収集時の設定は製品の既定(追加分割は同時 8 件、1 成分の早期除外あり)。
- 選び方: 左コントローラのビームで片の面を指して X を押し、その片をもう一度斬る。押下時の片の状態と、その後の斬撃の経過を保存した。

## 分かったこと

1. **元の Convex 集合に、車体 Mesh の内部を覆っていない領域があった。** `car_030` の Convex は 8 個。車体 Mesh の内側に取った点のうち、どの Convex にも入らない点が約 47 % あった(Mesh の箱の中に一様に取った 6000 点のうち内側 3057 点での割合。点の取り方に依存する目安)。5 件の指定点はいずれも、元の車体 Mesh の内側で、元の 8 個のどれにも入っていない。
2. **通常切断でその領域がキャップとして露出し、見える面と斬撃の命中対象との間に距離が生じていた。** 斬撃の命中は Convex に対して判定する。切断面(キャップ)は Mesh の内部まで描かれるので、Convex のない所に面だけが見える。
3. **指定点から保存した Convex までの距離**は次のとおり。

   | 選択 | 距離 |
   |---|---|
   | #1 | 約 98.1 cm |
   | #2 | 約 31.3 cm |
   | #3 | 約 31.8 cm |
   | #4 | 約 29.3 cm |
   | #5 | 約 107.6 cm |

4. **#5 の保存形状は、元の Convex を切り直したものと一致した。** 元の 8 個を、系統に保存されていた 16 面で順に切り直すと、残る Convex は 1 個で、保存形状との頂点差は最大約 1.7 µm だった。保存形状は通常切断の結果そのもので、途中で形状が壊れたわけではない。
5. **#2〜#4 では通常切断が実際に完了していた。** 再斬撃は命中として受け付けられ、発行された切断は最後まで完了している。切り落とされたのは主片の端で、主片そのものは残った(#2 → #3 → #4 は親子で、三角形数は 720 → 680 → 574)。指した面の近くが切れなかったので「切れない」と見えた。
6. **5 件とも Mesh は Topology 上閉じている。** Boundary 辺(1 面だけが使う辺)は 0。既存の切断入力検査も 5 件とも受理する。
7. **#5 は追跡の途中で回収された。** 所有者の退役と、台帳上の Retired への変化が記録されている。この片への命中も切断も記録されていない。**回収した処理の名前は特定していない**(記録に残る情報では分からない)。

#1 と #5 では再斬撃の命中が 1 件もなかった。#1 は 8 回の斬撃すべてで、sweep の箱は片の箱に当たったが Convex には当たっていない。

## 結論

- 原因は Convex 集合の覆い方で、切断・命中判定・追加分割の処理は記録の範囲で意図どおり動いていた。
- 利用者が仕様どおりの挙動として受け入れた。コードと既定設定は変えていない。
- 調査のために一時的に足した収集・追跡のコードは取り下げた(リポジトリには残していない)。
