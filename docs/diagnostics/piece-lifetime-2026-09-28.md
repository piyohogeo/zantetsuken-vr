# 片の寿命管理（DESIGN §7.10）実装記録（2026-09-28）

commit／push は行っていない。先行する未コミット変更（MobPlan の補充、DirectSkin の再利用など）は `C:\log\zantetsuken-vr\MobPlanSlash\gc-base\` に保存し、本件の差分と分けている。

## 対象と選び方

- 対象は、NPC の系譜から生じた切断片だけ。
  - 系譜の根（キャラクター）は `CutFragmentLifetime.MarkLineage` で登録する。登録は `VpPreparedCharacterCut` が、準備済みの根を表示した直後に行う。
  - 切断で生じた片（ledger に origin がある片）のうち、根が登録済みのものを対象にする。
  - 未切断の NPC、建物、プロップは対象外。
- 選び方：
  - 生存する対象片の数が、しきい値を超えている間だけ退役させる。
  - 片の bounds が視点から一定距離以上離れていて、かつ両眼のどちらの視野にも入らない片を選ぶ。
  - bounds は、物理形状の local box（`PhysicsOwnerShape.TryLocalBounds`）を Owner の位置・姿勢と `LocalToOwner` で置いた world AABB。Actor の原点では判定しない。
  - 視野の判定は、既存の `VpInstanceCulling.GetEyePlanes`／`MayIntersectAnyEye` を使う（ステレオなら両眼の frustum、モノなら 1 つ）。
  - Sleep は条件にしない。フェード・VFX・強制 Sleep は加えない。
- 巡回：
  - Owner 登録の片を 1 巡分コピーし、対象だけに絞って数える。
  - 1 フレームあたり、調べる件数と退役させる件数に上限がある。1 巡を終えてから次の巡を作る。

## 退役（既存の単独退役）

`CutFragmentLifetime.TryRetire` の処理：
1. 直前の確認：
   - World が変更を受け付けていること
   - 片が生存していること
   - 対象の系譜の片であること
   - 片自身に進行中の Operation も Provisional の組もないこと
   - Owner がこの World にあり、その Body が同じ片へ戻ること（退役の権限）
   - 集約の中で描かれていないこと
2. `Ledger.Retire`（後から届く結果は Stale になる）
3. `Owners.Retire`（Actor・Collider・Hit 形状を外す。共有 bank は他の利用者が持ち続ける）
4. `CutDag.Forget`

- 別の片の切断や、この片の Geometry の未完成は、理由にしない。
- GC 用の Operation、Pending Cut、Transaction は作らない。

## 資源：返却され再利用できる範囲と、確保済みの容量

**返却され、次の切断や登録で再利用できる**
- Physics の Actor・Collider・Hit 形状：Owner の Release による。共有 bank は、最後の利用者が離れたときに返る。
- 表示の登録、表示インスタンス参照、Geometry 参照の slot：次の収集で採用した後に返る。
- Index 範囲：参照表の `TryRetireGeometry` → storage の `TryRetireIndices`。読み取り lease がある間は Retiring を経て Free になり、次の予約で再割当される。
- CutDag の対応。

**返却されない**（§7.10 の資源回収としては未完了）
- 頂点ブロック（VB）：§4.5.3 の頂点の再利用は未実装。頂点は追記だけ。子は親の頂点ブロックを継承して参照するため、片を退役させても頂点の範囲は空かず、次の切断で再利用できない。§4.5.3 の頂点の再利用は、今回の異常を解消した後の別の単位に残す。
- ledger の片と Operation の記録（ID は再利用しない）。
- 系譜の根の登録（`MarkLineage` の集合）。

**確保済みの容量**（返却とは別の話。縮めないのは設計どおり）
- CPU の commit 済みページ（頂点・Index）、GPU の Buffer 容量、表示の Snapshot と作業領域の容量。いずれも拡張した大きさのまま残る。
- 返却された Index 範囲は、この容量の中で再利用される。

## 現在の実装の制限

- 集約の中で描かれている片（最初の Ignored 境界より先の枝）は、退役の対象から外している（残件として保持）。表示が、集約の中の退役を停止理由として扱う（`RetiredInsideAggregate`）ため。
- これは現在の実装の制限で、寿命管理の仕様として固定するものではない。

## 既存経路への最小の接続

- `PhysicsOwnerRegistry.CopyFragmentsTo`：巡回用。
- `VpLogicalCutDisplay.IsDrawnInsideAggregate`：集約の中の片を退役させると、表示が停止する（`RetiredInsideAggregate`）。それを避けるための確認。
- `CutDag.Forget`：生存中に退役した片の対応を消す。
- `CutDag.Settle`：Commit の時点で退役している側を登録しない（後着の結果で復活させない）。
- `CutWorldRoot.Lifetime`：`LateUpdate` で 1 フレームに 1 回進める。その Frame の表示の収集より前なので、退役した片は同じ Frame で物理と描画から外れる。

## 試験（PlayMode、`CutWorldRootPlayModeTests.PieceLifetime.cs`、5 件）

- 無効のとき、予算が足りないとき、切断中の片では、新しい退役を始めない。兄弟の片は、その片自身の状態だけで判断する。
- 退役させた片は、表示・物理・Hit から外れる。Geometry 参照と Index 範囲が返る。頂点は返らない。兄弟の片は残る。
- Geometry が未完成の片を退役させても、後から届く結果で復活しない。
- 残った片を、通常の切断で再び切断できる。
- 選び方：遠く、見えない、登録済みの系譜の片だけを、しきい値まで退役させる。
- どの試験も World を終了させ、fixture による release と回収の確認を通す。

## 統合確認で見つかった異常と、その切り分け（2026-09-28、TL 採用：対象片の選択・退役と、現在回収できる資源の返却まで。§7.10 全体の完了ではない）

x18（有効）と x19（無効）の両方で、check の scenario が 2 件失敗した（姿勢の一致、枠の再利用の順序）。

- **時系列**（x18：r1003・枠 11・3 回目の起動・Operation 80・source 199。x19：a14・Operation 42）
  1. 命中
  2. その Frame の姿勢を適用（applied frame が命中 frame、source 1.1167／0.3500）
  3. 受付
  4. 退役
  5. Provisional
  6. 次の Frame で Final・Commit
  7. 6 フレーム後に、枠を次の個体へ再起動
- **製品の順序に誤りはない**：受付・公開・Commit は枠の再利用より前に済んでいる。姿勢も、命中の Frame に適用したもの。
- **原因は、退役時の観測漏れ**：crowd は、命中した個体を、命中と同じ Frame の自分の Update の中で計画から外すことがある。起きた回数は、x18・x19 で各 1 回、x14・x16・x17 で 0 回。その場合、check が命中を読んだ時点では、次のようになっていた。
  - check は、系譜の根の名前を Frame ごとに記録するが、退役済みの個体は飛ばしていた。そのため根 199（a14 では 107）の名前がなく、枠の新しい handle でも引けず、「受け付けられた切断がない」と判断した。
  - 計画は、すでにその個体を返せなかった。そのため姿勢の比較が「計画なし」になった。
- **補正**（観測用イベントと check の補正。check だけの変更ではない）：
  - 製品側（Sandbox の crowd）：観測用イベント `MobPlanCrowd.ActorRetired` を、計画から外す直前に通知するようにした。購読者は check だけ。計画からの除去、LOD、枠の返却の順序と時点は変わらない。
  - check 側：退役の通知で根の名前と、その時点の計画の評価（同じ時刻）を記録する。命中と同じ Frame に退役していた場合だけ、その評価と比べる。
  - この 2 つは一組の変更で、片方だけでは成立しない。
  - DirectSkin の返却条件と、命中のたびに現在の姿勢を取り直す条件は、変えていない。
