# Releaseからの詳細計測の除外と、同意に基づく軽量なプレイ統計（検証記録、2026-10-14）

設計は DESIGN.md 21.18、決定は D-226〜D-231、未決は O-054。この文書は、何をどの条件で確かめ、何を確かめていないかの記録である。

**状態：Development・Linkで集計条件を確認済み。配布の準備完了ではない**（2026-10-14、TL判断）。次の単位は、送信なしのRelease Playerでの確認と、同じRelease Playerでの統計ON／OFFの比較である。

生の記録（Playerのログ、試験結果、ビルドの記録、作業の経過 `RELEASE-STATS-1.md`）は計測記録のフォルダにあり、リポジトリには含めない。送信設定（送り先とトークン）、ビルドしたPlayer、受信側から取得した実データも含めない。

## 1. 条件

- Unity 6000.3.22f1、URP、IL2CPP。Windows 11、Direct3D 12、Quest Link（OpenXR）、描画GPUは RTX 3090。
- Playerは引数なしの `play`（WalkCity：群衆20体と配置物885個）。同意は保存済み（Agreed）。
- 形式2の確認（4章）では送信設定を持たないPlayerを使い、外部へは何も送っていない。

## 3. 形式1で確かめたこと（開始条件の修正前）

- 通常終了の記録：フォーカスを一度も失わない実行でも、Development・Releaseの両方で終了時の記録が残る。
- 終了時の待ち（ローカルの受信側）：受理は0.01秒、時間切れは2.01秒で通信を中止、失敗は0.00秒。どれでも終了する。
- 実送信：Editorから作り物の記録1件（201、731 ms）、Release Playerから実際の統計1件（3,203バイト、201、終了の待ち0.15秒）。2件とも受信側の保存先から読み戻し、Playerのログの値と一致した。本文に機器名・利用者名は無い。
- 保存済みの2件は、Worldの準備済みから数えていた形式1の記録で、起動のフレームを含む。削除せず「開始条件修正前」として残す。

## 4. 形式2の確認（Playerのログより）

3回の起動。どれも例外0、終了コード0、ウィンドウを閉じて終了。

| | 1回目 Development | 2回目 Release | 3回目 Development |
|---|---|---|---|
| Worldの準備／プレイの開始（フレーム） | 394／504 | 395／505 | 361／471 |
| 起動準備（始まり／終わり、件） | 886／886 | 886／886 | 886／886 |
| サンプラの読取り（＝サービスの更新） | 13,825 | 9,427 | 5,112 |
| プレイの開始前（数えない） | 110 | 110 | 110 |
| ゲームの一時停止の間（数えない） | 0 | 723 | 0 |
| XRのセッションのフォーカス外（数えない） | 0 | 0 | 807 |
| 境界の直後の1フレームずつ（数えない） | 2 | 3 | 3 |
| 数えたフレーム | 13,713 | 8,591 | 4,192 |

| サービスの更新の平均（同上） | 10.84 µs | — | 11.37 µs |

- **プレイの開始。** 3回とも、Worldの準備から110フレーム（約5.0〜5.2秒）後に始まり、それより前は数えていない。群衆と配置物のある街で、起動準備の件数は0に届く。
- **一時停止。** 2回目はゲームのメニューを1回開いた（723フレーム）。その間と、再開の直後の1フレームを数えていない。
- **デスクトップのフォーカス。** 3回目はウィンドウのフォーカスを1回失った。その時点の記録は開始後の全フレームを数えており（1,850 − 110 − 2 ＝ 1,738）、喪失は境界になっていない（帰属させないフレームは実行全体で16のまま）。
- **システムメニュー。** 3回目は、OpenXRのセッションが8.93秒のあいだFOCUSEDを離れてVISIBLEになった。Linkのシステムメニューはセッションのフォーカスを外す。その間のフレームを数えていない。
- **3回目の合計。** 5,112 ＝ 110 ＋ 2 ＋ 808 ＋ 4,192 で整合する（808はフォーカス外の807と復帰直後の1）。8.93秒×90 Hzは約804フレームで、3フレームの差がある。90 Hz×経過秒は実際の更新の回数と厳密には一致しない。**差の原因は確定していない。**
- **環境の値。** グラフィックスAPIは `Direct3D 12 [level 12.2]`、GPUのドライバは `32.0.15.9159`（IL2CPPのPlayerでレジストリから読めた）、XRのランタイムは `Oculus` `1.208.0`（`OpenXRRuntime`）、XR機器の名前はnull（未取得）。
- **視点の行。** 追跡の原点はFloor、カメラのオフセットは0、頭はリグから約1.04 m。3回とも座った状態だった。アプリは高さを足しても引いてもいない。
- **Releaseに無い行。** 2回目のログには、遅れの観測の行とサービスの費用の行が無い（Developmentだけの出力）。

## 5. 確かめていないこと

| 項目 | 扱い（2026-10-14、TL判断） |
|---|---|
| XRのフォーカスの2点をRelease Playerで | 次の単位で確かめる |
| Releaseでのサービス自身の費用 | Developmentの約11 µsをReleaseの費用としない。同じRelease Playerの統計ON／OFFの比較で確かめる。直接の計測が要るなら検証専用に限る |
| 時間の遅れの上限8フレーム | このPCの実測は常に5。暫定値として維持する。全ての環境で帰属を保証したとは扱わない |

| 描画側のGPUのドライバの選択 | 確認した機材は2枚が同じ版で、実測では区別できない。異なるIDと版を与える選択の試験（`PlayStatisticsStartTests`）で補う。検証のためにドライバを変えない |
| 立った状態での視点の高さ | 統計の確認とは別。表示・操作の確認のときに見る |
| Quest（Vulkan）の全項目 | PCVRの確認で代用しない。Questの配布前に確かめる |
| 保持期間、`tester_role` の配り方、受信側の制限、トークンの配布 | 未決（O-054） |

## 6. 別件として分けたもの

- 配置物のPlayMode試験の失敗（2章）。既存の回帰疑いとして原因を調べる。期待値を変えて済ませない。
- Linkのシステムメニューの間もゲームの進行が止まらないこと（3回目のログに、ゲームの一時停止の行が無い）。統計のフォーカスの判定からゲームを止めない。停止の方針を決めてゲーム側で扱う。
